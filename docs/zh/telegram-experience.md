# Telegram 主通道：能力评估与接入顺序

日期：2026-10-06。Telegram 是主使用通道；微信保留文字菜单基础，观察模式的消息收纳方案明确后再扩展。

## 官方能力与 FoxClaw 的用途

官方最新列出的版本为 Bot API 10.3（2026-08-24）。10.1 加入富消息，10.2 加入群内定向临时消息，10.3 增加草稿停止控制和禁用按钮。[官方更新记录](https://core.telegram.org/bots/api#recent-changes)

| 优先级 | 能力 | 产品用途 | 当前状态与边界 |
| --- | --- | --- | --- |
| P0 | 编辑消息、富消息 | 一条任务进度卡，完成后换成结果；保留模型、权限、审批入口 | 统一任务路径已实现；私聊草稿与群聊持久卡分别管理，结果交付前结束预览。存量观察展示待收敛 |
| P1 | 草稿原生停止按钮 | 手机直接停止正在生成的回复 | 已接入。只停止对应任务，保留排队任务；群聊和草稿不支持时使用卡片按钮。等待原生取消完成后释放任务槽位 |
| P1 | 折叠内容、结构化块 | 摘要常驻，工具过程和长日志折叠；需要时查看完整结果 | 统一任务已实现回答在前、执行摘要折叠在后；长摘要限长，长回答按需分块。外部观察卡待统一 |
| P1 | 禁用按钮 | 正在切换账号、启动或取消任务时明确展示暂不可用的操作 | 待接入。后端仍必须验证操作有效性，展示状态不能代替校验 |
| P2 | 群内仅本人可见的临时面板 | 账号、模型和个人设置不占公共群消息流 | 待接入；需要独立处理临时消息标识、回调用户与删除/编辑接口 |
| P2 | 复制文本按钮 | 复制工作目录、恢复命令、任务编号 | 按场景加入，优先采用菜单可直接完成的操作 |

草稿停止使用 `can_stop`、`keep_on_stop` 和 `stopped_message_generation` 更新。草稿限私聊且是临时预览，最终回答仍需发送持久消息。停止事件只携带聊天、主题和草稿编号，必须与当前任务匹配，忽略过期事件。[草稿接口](https://core.telegram.org/bots/api#sendrichmessagedraft)、[停止事件](https://core.telegram.org/bots/api#messagegenerationstopped)

禁用按钮和颜色由 Telegram 键盘类型支持；群内个人面板需要定向临时消息及其专用编辑接口。[键盘按钮](https://core.telegram.org/bots/api#inlinekeyboardbutton)、[临时消息参数](https://core.telegram.org/bots/api#ephemeralmessageparameters)

不把这些功能一次性塞入共享调度器。Telegram 通道声明展示能力并转换事件；调度器只处理任务状态、操作归属和取消结果；各后端提供自己的模型、权限与审批能力。

## 推荐的任务与观察展示

1. 每项任务维护一条进度卡：引擎、阶段、耗时、最近一项工具活动、停止入口。
2. 增量内容合并、节流编辑，普通工具活动不新增聊天消息。
3. 审批单独展示，保持明确的任务归属；完成后更新或撤销过期操作。
4. 最终结果显示结论与必要证据，长过程折叠；文件按需提供。
5. 观察外部会话沿用相同的信息结构，但保持只读语义。新增输入应明确排队或接管，不因展示重构而暗改。

本轮已落地“单条进度卡 → 停止操作 → 完成后折叠摘要”，覆盖 Telegram 的 Codex / AGY / DSH 统一任务路径。草稿使用同一个编号刷新，运行期间保持更新；完成或停止后清除草稿并发送持久结果。停止事件验证允许的私聊、主题和当前草稿；群聊停止回调还验证用户与具体任务编号。旧按钮与旧草稿不会停止后来启动的任务。

暂未接入定向临时设置面板和禁用按钮，存量外部会话观察展示也未统一。原生 API 能力有自动化模拟验证，手机上的实际交互效果需要上线后由用户验收。

## 微信进入实用阶段的条件

微信无法原地编辑进度卡，建议采用“开始提示 → 必要里程碑 → 最终摘要”。合并重复工具消息，不逐段推送生成文本；失败、审批和需要用户介入时即时提示。

已接受使用文字菜单和命令。本轮增加有会话归属、有效期和单次使用约束的 `/choose` 操作。统一观察摘要、历史整理和完整多后端接入保留为后续工作，不先扩大微信使用范围。
